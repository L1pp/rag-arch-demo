## Boundaries retained

- OCR is disabled by default. Its current adapter uses the documented ordinary Alibaba Cloud endpoint and fixed OCR model; credentials and materials are supplied by the operator. Recognized text remains unverified.
- Interrupted tasks are isolated only after confirming the local worker and registered resources have exited. External request completion remains unknown and no automatic retry is added.
- Corpus mmap opening no longer compares the source directory. Operators manage source/index versions and rebuild matching packages; structural validation remains.
- Private history, real corpora/plans, database contents, OCR caches, service credentials and deployment identities are excluded. This snapshot is submitted through a PR and is not automatically merged.

## GitHub review follow-up

The [first CI run](https://github.com/L1pp/rag-arch-demo/actions/runs/40905889713) ran all 550 backend tests with no skips and passed 82 frontend tests, including PostgreSQL and Linux LibreOffice.

Follow-up fixes address cross-registry original-file links and lost regions, OCR failure blocking page-only chat, and stale Office markers blocking later conversions. Marker retirement holds the conversion lock, rechecks identity and complete exit proof, and requires database acceptance; unknown or new owners remain untouched. No-text OCR results skip memory caches while durable failed/unknown markers still fence repeat requests; async shared-build cancellation retries preserve that admission policy. Path keys use OS case semantics to keep distinct Linux originals separate.

One local full run exposed a synthetic PDF worker startup competing with a three-second operation deadline. The fixture now performs bounded readiness first, then restores all existing deadline/identity assertions; production limits were unchanged. The final local totals above include these regressions; consult the PR's latest CI for service-backed validation.
